# Person

Create a stable ID when adding a person, for example `person_` followed by a
random UUID. Keep it when copying the note to another collection or renaming
its file. Apps use this ID for assignments and other person references.

```yaml
type: person
id: person_2c1343ec-cac1-4d58-98c9-41736f4de7db
name: Callum
identities:
  - issuer: https://connect.example
    subject: usr_789
```

Use the actual issuer and subject supplied by Connect, not the example values.
Omit `identities` for people without accounts. Email is contact information,
not a way to establish an identity association. Linking a person does not
invite them or grant access to this collection.

Identity associations and contact labels are ordinary editable data. They are
not proof of authentication. Avoid duplicate person IDs or identity pairs
across person notes; applications must report ambiguity rather than guess.

The inline schema belongs to the collection. Add local fields or rename them
and update the explicit contract mappings without editing published contracts.
